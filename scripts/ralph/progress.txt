## Codebase Patterns
- Python CLI 使用标准库 `argparse` + `pathlib`，输入校验必须发生在任何遍历或写入之前；行为测试使用 `unittest` + `tempfile` + `subprocess`
- `skills/<name>-profile/` 是被 .gitignore 忽略的个人 profile 目录；下游 runtime 仍可加载
- nuwa-skill 的研究材料命名固定为 `references/research/01-XX.md` 到 `06-XX.md`，合并工具 merge_research.py 按文件名扫描
- 公众人物 quality_check.py 当前不区分 profile_type；新增 self 模式需要在 frontmatter 检测后切换校验
- 自我蒸馏工作流文档统一引用单一规范；任何 story 在进入 self 流程前必须先读 references/self-distill-workflow.md，不得从 SKILL.md 重新猜测 class/checkpoint
- self 模式默认纯本地：除非用户明确要求，不联网佐证；外部材料只允许在 references/research/ 对照，不进入 assets/
- 在 `/Volumes/WorkSSD/Cache/tmp`（APFS firmlink）上用 `subprocess.run` 调子进程创建的文件，父进程在同一 `tempfile.mkdtemp` 内 `Path.is_file()` 经常读不到（firmlink 写完后元数据同步延迟）；测试优先 import 被测模块后直接调函数，避免 `subprocess.run`，并在 finally 内做完所有断言再 `shutil.rmtree`
- source-policy.json 字段名 `schema_version` / `rules[].class` / `rules[].globs` 与合法 class 枚举（authored/private-evidence/adapted/external/excluded）由 US-006 锁定；后续 quality_check / merge_research / US-013 文档引用时必须复用同一名称与顺序，class 集合不得新增
- inventory 的 record 字段顺序是 manifest 的事实契约：US-006 仅在 `_build_manifest` 内引入 `can_distill` / `unmatched_count` 计算，不修改 record 字段集合；US-007+ 增加 sha256/duplicate_group/version_group/semantic_read 时同样保持 record 键名稳定
- `_glob_matches` 实现 `**/`（零或多层目录）与 `**`（任意字符）语义；`fnmatch.fnmatch` 与 `pathlib.PurePath.match` 都不直接支持 `**/`，不要在 story 中临时替换
- duplicate_group 用 sha256 字符串作为稳定标识；representative 以 eligible 文件中 relative_path 字典序最小者为准；reading budget 只对 semantic_read=true 的 representative 计数
- 版本序列字段顺序：US-008 在 record 中新增 `version_group` / `current_version` / `evolution_only`；version_group 形如 `{parent_dir}/{base_name}v{highest}{ext}`（或 root-level 时去掉前缀），与 duplicate_group 一样是「跨字段稳定字符串」；sorted 时必须用「数字 tuple + relative_path」复合 key，避免 V10 < V2 的字典序误判
- inventory review 在 重复文件 段之后追加 版本序列 段（version_groups + current_version 路径 + 注释），保持 markdown 列表格式 `- \`path\`` 不变，让 Nuwa 后续 story 可直接 rg 提取
